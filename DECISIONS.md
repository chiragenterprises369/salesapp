| D-069 | Change #19 wave C integration hub and webhooks: every provider (IndiaMART, WhatsApp Cloud API, telephony mock/Exotel, SMTP, Google Calendar) sits behind an adapter with a `live` and a dev-only `mock` mode; secrets are validated per provider, encrypted with ENCRYPTION_KEY and shown back only as masked hints; tokens Vistar generates for a provider (IndiaMART push key, WhatsApp verify token, telephony callback token) are visible to integrations.manage. All `/api/hooks/*` receivers live in one controller so literal paths match before `{workspaceId}/{sourceKey}`; the telephony callback moved to `/api/hooks/{workspaceId}/telephony/{provider}`. | D-076 | Change #20 production (PROD-HUB). Strict boot (`infra/prod/production-config.ts`): with NODE_ENV=production the API refuses weak or example secrets, equal JWT secrets, a non-random ENCRYPTION_KEY, http or localhost public URLs, `*` origins, missing Redis, a weak database password, DEV_AUTH, dev CORS ports, the private-host allowlist, `STORAGE_DRIVER=local`, mock billing or telephony, mock web data and SEED_DEMO; panel-owned settings (mail, storage credentials, Sentry, Razorpay, Firebase) are checked by the go-live checklist instead so a new server can boot and be configured. Logs: one JSON line per entry with request id, user and workspace from AsyncLocalStorage, every message redacted (e-mails, phones, tokens, passwords, GSTIN, PAN), IPs truncated, access log without query strings. Limits: per-IP fixed windows in Redis for sign-in, public, file and webhook routes (middleware) and per-user after the guards (interceptor); 100 KB bodies. `/api/ready` (db, Redis, storage, draining) next to `/api/health`; SIGTERM sets draining, waits SHUTDOWN_DRAIN_MS, closes HTTP and runs the Nest shutdown hooks, hard exit after SHUTDOWN_TIMEOUT_MS. Errors go to a Sentry-compatible envelope endpoint without an SDK (panel config first, SENTRY_DSN fallback, 30 reports a minute). Deployment: one Compose stack (Caddy with on-demand TLS asking `/api/tls/ask`, web standalone, api, optional worker, Postgres 17, Redis 7 noeviction with AOF, backup job) with non-root read-only containers, resource limits and a separate tools image for migrations and the clean seed; backups are custom-format pg_dump, optionally AES-256 encrypted, sha256, uploaded to S3 or Bunny with local and remote retention; CI builds and checks without deploy secrets | Production must never run on dev defaults, and the operator needs one documented path (DEPLOY.md, RUNBOOK.md) on a single server; no new dependencies (helmet, nodemailer, google-auth-library and the AWS SDK were already there) |
